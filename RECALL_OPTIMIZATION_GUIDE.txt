================================================================================
                      THRESHOLD SELECTION
================================================================================

The model provides THREE threshold recommendations:

1. MAXIMUM RECALL (e.g., 0.15-0.25)
   → Catches 99%+ of declines
   → Many false positives (flags many passes as declines)
   → Use if: Missing ANY decline is catastrophic

2. OPTIMAL RECALL (e.g., 0.25-0.35)  ← RECOMMENDED
   → Catches 95-98% of declines
   → Reasonable false positive rate
   → Use if: Balance is needed but recall is priority

3. BALANCED (e.g., 0.4-0.5)
   → Catches 85-90% of declines
   → Lower false positives
   → Use if: False positives are also costly

RECOMMENDATION FOR YOUR CASE:
Use threshold between 0.2-0.3 based on:
  - How costly is missing a decline? (lower threshold)
  - How costly is a false alarm? (higher threshold)

================================================================================
                      TROUBLESHOOTING
================================================================================

Q: Recall is still low (< 90%)
A: 1. Increase time_limit to 3600+ seconds
   2. Use preset='best_quality'
   3. Try resampling_method='smote' in advanced pipeline
   4. Lower threshold to 0.2 or 0.15
   5. Check if features are informative enough

Q: Too many False Positives
A: 1. This is expected when optimizing for recall
   2. Increase threshold slightly (0.3 → 0.35)
   3. Consider cost-sensitive threshold optimization
   4. May need to accept higher FP for lower FN

Q: Model training is slow
A: 1. Start with good_quality preset for testing
   2. Reduce num_bag_folds to 5 (in code)
   3. Use more powerful hardware
   4. The deep ensemble is necessary for best recall

Q: Want to balance recall and precision better
A: 1. Use find_optimal_threshold(results, metric='f1')
   2. Or use metric='cost_sensitive' with your actual costs
   3. Or manually set threshold based on business requirements
