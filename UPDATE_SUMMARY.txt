================================================================================
                          WHAT CHANGED
================================================================================

1. EVALUATION METRIC
   Before: eval_metric='roc_auc' (general performance)
   After:  eval_metric='recall' (minimize False Negatives)
   Impact: Model selection now prioritizes catching minority class

2. CLASS WEIGHTING
   Before: Balanced weighting (minority_weight = 77x for 155:1 ratio)
   After:  AGGRESSIVE weighting (minority_weight = 310x)
   Impact: Model treats missing a decline as 2x more critical

3. HYPERPARAMETERS - Gradient Boosting
   Before:
     - num_boost_round: 1000
     - learning_rate: 0.01
     - max_depth: 6
     - min_child_weight: 5 (conservative)
   
   After:
     - num_boost_round: 2000 (more iterations)
     - learning_rate: 0.005 (slower, better generalization)
     - max_depth: 8 (deeper trees for complex patterns)
     - min_child_weight: 1 (more sensitive to minority)
   
   Impact: Model can capture more subtle patterns in minority class

4. HYPERPARAMETERS - Random Forest & Extra Trees
   Before:
     - class_weight: 'balanced'
     - max_depth: 15
     - min_samples_leaf: 5
   
   After:
     - class_weight: 'balanced_subsample' (more aggressive)
     - max_depth: 20 (deeper)
     - min_samples_leaf: 1 (more sensitive)
   
   Impact: Trees can split more aggressively on minority patterns

5. CROSS-VALIDATION
   Before: 5 folds
   After:  8 folds
   Impact: Better coverage of minority class in validation

6. ENSEMBLE DEPTH
   Before: 1 stacking level
   After:  2 stacking levels
   Impact: Deeper ensemble learns from more diverse models

7. DEFAULT THRESHOLD
   Before: 0.5 (standard)
   After:  0.3 (lower for better recall)
   Impact: More predictions classified as declines

8. MODEL SELECTION
   Before: Included Neural Networks with multiple configs
   After:  Removed Neural Networks (not needed for tabular)
   Impact: Faster training, focus on effective tree-based models

9. HYPERPARAMETER LISTS
   Before: Multiple configurations per model (lists)
   After:  Single optimal configuration per model (dict)
   Impact: Cleaner code, faster training, no redundancy

10. EVALUATION OUTPUT
    Before: Generic metrics display
    After:  Detailed False Negative analysis with cost breakdown
    Impact: Clear visibility into primary optimization goal

================================================================================
                      QUESTIONS & SUPPORT
================================================================================

Q: Why remove Neural Networks?
A: For tabular data with 24 numerical features, tree-based models (GBM, XGBoost)
   perform better and train faster. NNs add training time without improving recall.

Q: Why aggressive weighting instead of SMOTE?
A: Both are provided! Aggressive weighting is faster (no data augmentation).
   SMOTE is available in advanced_autogluon_pipeline.py if needed.

Q: What if I want to optimize for F1 instead?
A: Change eval_metric='f1' when calling train_autogluon_model()

Q: How do I tune the threshold after training?
A: Use find_optimal_threshold(results, metric='recall') or manually set:
   evaluate_model(predictor, test_data, threshold=YOUR_THRESHOLD)

Q: Can I see all the code changes?
A: Compare the updated .py files with your originals using a diff tool
